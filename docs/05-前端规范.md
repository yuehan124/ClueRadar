# 05 · 前端规范

> **适用范围**：本规范约束 `frontend/` 下的正式前端。`prototype/` 只是产品原型，
> 用于交互评审与设计参考，不参与生产构建与部署；正式代码不得写进 `prototype/`。

## 1. 技术栈

| 项 | 版本 | 说明 |
|---|---|---|
| Vue | 3.5 | 组合式 API + `<script setup>` |
| TypeScript | 5.x | 严格模式 |
| Vite | 6 | 构建与开发服务器 |
| Element Plus | 2.9 | 中后台组件 |
| Pinia | 2.3 | 状态管理 |
| ECharts | 5.5 | 图表 |
| Vue Router | 4.5 | history 模式 |

## 2. 目录结构

```
frontend/src/
├── api/            # 接口封装：baseURL、请求、错误归一化
├── components/     # 可复用组件（不带业务状态）
├── layouts/        # 布局：侧边栏、顶栏、用户菜单
├── mock/           # 离线开发假数据（生产构建不得依赖；原型数据见 prototype/src/mock）
├── router/         # 路由表与全局守卫
├── stores/         # Pinia
├── styles/         # 全局样式与 CSS 变量
├── types/          # 领域类型
├── utils/          # 纯函数（无副作用）
└── views/          # 页面
```

约束：

- **页面不直接 `fetch`。** 所有网络请求走 `src/api/`。
- **工具函数不依赖 Vue。** `utils/` 必须能在 Node 里单独运行。
- **`components/` 不放业务数据。** 业务状态由页面或 store 注入。

## 3. 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 页面组件 | PascalCase + `View` 后缀 | `LeadsView.vue` |
| 通用组件 | PascalCase | `LeadDetailDrawer.vue` |
| 组合式函数 | `use` 前缀 | `useLeadFilters.ts` |
| store | `useXxxStore` | `useLeadStore` |
| 类型 | PascalCase | `ScoreBreakdown` |
| 常量 | UPPER_SNAKE | `STAGE_LABEL` |
| CSS 类 | kebab-case | `.lead-card` |

## 4. 单文件组件

固定顺序：

```vue
<template>
  <!-- 只做结构，复杂表达式提取到 computed -->
</template>

<script setup lang="ts">
// 1. imports
// 2. props / emits
// 3. 组合式状态
// 4. computed
// 5. methods
// 6. 生命周期
</script>

<style scoped>
/* 只写本组件样式 */
</style>
```

规则：

- 一律 `<script setup lang="ts">`，不用 Options API。
- `defineProps` / `defineEmits` 必须带类型：

```ts
const props = withDefaults(defineProps<{ lead: Lead; score: ScoreResult }>(), {
  score: () => ({ total: 0, grade: 'C', breakdown: [] }),
})
const emit = defineEmits<{ (e: 'update', id: number): void }>()
```

- **禁止**在模板里写复杂逻辑（超过一个三元或一次方法调用就提 `computed`）。
- **禁止**用 `any`；确实未知用 `unknown` 并收窄。

## 5. Pinia

- 一个领域一个 store：`auth` / `leads` / `keywords` / `system`。
- **派生数据放 getter**，不存冗余 state。例如评分、筛选结果、统计都由
  `scored` → `filtered` → `paged` 链式派生。
- action 只做"改变事实"的操作；不做格式化展示。
- 组件不直接改 store state，必须调 action。

```ts
// 正例：派生而非存储
getters: {
  scored(state) {
    return state.leads.map((lead) => ({ lead, score: calcScore(lead, state.weights) }))
      .sort((a, b) => b.score.total - a.score.total)
  },
}
```

> 现有实现中，权重变化后排序立即重排，正是因为它由 getter 派生。
> 如果把排序结果存进 state，就会出现"改了权重但列表不动"的 bug。

## 6. 路由

- history 模式，base **必须**用 `import.meta.env.BASE_URL`：

```ts
history: createWebHistory(import.meta.env.BASE_URL)
```

- `meta` 约定字段：`title`、`desc`、`menu`、`icon`、`public`。
- 鉴权守卫：

```ts
router.beforeEach((to) => {
  const auth = useAuthStore(pinia) // 显式传实例，不依赖 active pinia
  if (!auth.user) auth.restore()
  if (!auth.isLoggedIn && !to.meta.public) {
    return { name: 'login', query: { redirect: to.fullPath } }
  }
  if (auth.isLoggedIn && to.name === 'login') return { name: 'dashboard' }
  return true
})
```

- 守卫里**必须显式传 pinia 实例**，因为守卫可能在 `app.use(pinia)` 之前执行。
- 新增受保护页面不需要改守卫；只有 `public: true` 的页面会跳过。

## 7. 接口层

```ts
// src/api/client.ts
const BASE = `${import.meta.env.BASE_URL}api/v1`.replace(/\/+/g, '/')

export async function request<T>(path: string, init?: RequestInit): Promise<T> {
  const res = await fetch(`${BASE}${path}`, {
    ...init,
    headers: { 'Content-Type': 'application/json', ...authHeader(), ...init?.headers },
  })
  const body = await res.json()
  if (!res.ok || body.code !== 0) throw new ApiError(body.code, body.message, body.traceId)
  return body.data as T
}
```

- 401 统一在拦截层处理：清登录态 → 跳登录 → 带 `redirect`。
- 错误提示只在一处弹（请求层），页面不重复 `ElMessage.error`。
- 后端未就绪时用 `mock/` 兜底，但**同一份类型**，避免字段漂移。

## 8. 样式

- 组件样式一律 `scoped`。
- 颜色、圆角、间距优先用 `src/styles/main.css` 中的 CSS 变量：

```css
:root {
  --brand: #4f6ef7;
  --brand-2: #8b5cf6;
  --text-1: #1f2333;
  --text-2: #414a63;
  --text-3: #6b7280;
  --radius: 10px;
  --bg-page: #f4f6fb;
}
```

- Element Plus 覆盖用 `:deep()`，且限制在组件内，不写全局选择器。
- 禁止用内联 `style` 表达主题色（布局微调可接受）。
- 字号阶梯固定：28 / 24 / 20 / 16 / 14 / 13 / 12（px），不随意新增。

## 9. 时间处理（强制）

时间有两个来源，规则不同：

| 来源 | 规则 |
|---|---|
| 后端返回的时间 | ISO 8601 带偏移（`2026-10-20T19:38:06+08:00`），前端用 `new Date(iso)` 解析后按本地时区展示 |
| 前端演示数据写入 | 用 `nowLocal()` 生成无偏移的本地时间串，与 mock 格式保持一致 |

```ts
// src/utils/index.ts
export function nowLocal(date = new Date()): string {
  const p = (n: number) => String(n).padStart(2, '0')
  return `${date.getFullYear()}-${p(date.getMonth() + 1)}-${p(date.getDate())}` +
         `T${p(date.getHours())}:${p(date.getMinutes())}:${p(date.getSeconds())}`
}
```

**禁止**用 `new Date().toISOString()` 生成要展示或入库的业务时间。它输出 UTC（带 `Z`），
直接展示会与本地时间相差 8 小时——这是原型阶段真实出现过的 bug。

- 写入业务时间：后端负责（`datetime.now(timezone.utc)` 存库）；
  原型阶段用 `nowLocal()`。
- 展示：`fromNow(iso)` 接受带偏移和不带偏移两种格式（`new Date()` 均能正确解析）。
- 禁止在前端做手工时区加减（如 `+8 * 3600 * 1000`）。

## 10. 状态与反馈

每个异步页面必须覆盖四种状态：

| 状态 | 要求 |
|---|---|
| loading | 表格/卡片骨架或 `v-loading`，不整页白屏 |
| empty | 明确文案 + 下一步动作（如"调整筛选"） |
| error | 展示 `message` 与 `traceId`，提供重试 |
| success | 正常渲染 |

- 破坏性操作（退出登录、删除词）必须二次确认。
- 成功提示用 `ElMessage.success`，同一操作不叠加多条。

## 11. 可访问性

- 可点击元素必须是 `button` 或带 `role`/`tabindex`，支持键盘 Enter/Space。
- 图标按钮必须有 `aria-label` 或 `title`。
- 表格行可点击时，需同时提供显式的"查看详情"按钮（键盘可达）。
- 文本对比度不低于 WCAG AA。

## 12. 性能

- 路由全部懒加载（`() => import(...)`）。
- 大列表用分页；单页不超过 100 条。
- ECharts 实例在 `onUnmounted` 时 `dispose()`，避免内存泄漏。
- 不在 `computed` 里做 O(n²) 计算；重活放后端。

## 13. 禁止事项

| 禁止 | 原因 |
|---|---|
| 硬编码 `/radar/` 或 `/` 作为路由/资源前缀 | 子路径部署会 404 |
| 组件内直接 `fetch` | 绕过统一错误与鉴权 |
| 用 `new Date().toISOString()` 写业务时间 | 8 小时时区偏差 |
| 在模板里写复杂表达式 | 可读性与性能 |
| 用 `any` 掩盖类型问题 | 类型形同虚设 |
| 把最终排序/统计结果存进 state | 权重变更后不刷新 |
| 在 `utils/` 里 import Vue 或 store | 破坏纯函数可测试性 |
