# 04 · 接口契约

## 1. 通用约定

| 项 | 约定 |
|---|---|
| 风格 | REST + JSON，UTF-8 |
| 内部前缀 | `/api/v1` |
| 外部访问 | `/radar/api/v1`（nginx 去掉 `/radar` 后转发） |
| 版本 | 路径版本化；破坏性变更升 `v2`，不原地改语义 |
| 时间 | ISO 8601 带时区偏移，如 `2026-10-20T19:38:06+08:00`；数据库存 `TIMESTAMPTZ`（UTC） |
| ID | 数据库自增整数，JSON 中为 number |
| 命名 | 字段 camelCase（与前端一致），后端用 Pydantic alias 转换 |
| 空值 | 统一 `null`，不用空字符串表示"无" |
| 布尔 | 真 `true` / 假 `false`，不用 0/1 |

## 2. 统一响应

### 2.1 成功

```json
{
  "code": 0,
  "message": "ok",
  "data": { },
  "traceId": "0f3c9a1e8b7d4c21"
}
```

- HTTP 状态码与语义保持一致（200 / 201 / 202 / 204）。
- `code = 0` 表示业务成功。
- `traceId` 同时写入响应头 `X-Trace-Id`。

### 2.2 失败

```json
{
  "code": 40101,
  "message": "未登录或登录已过期",
  "data": null,
  "traceId": "0f3c9a1e8b7d4c21"
}
```

### 2.3 错误码

| HTTP | code | 含义 | 前端处理 |
|---|---|---|---|
| 400 | 40001 | 参数校验失败 | 表单标红，展示 `message` |
| 401 | 40101 | 未认证 / token 过期 | 清除登录态，跳登录页 |
| 401 | 40102 | 账号或密码错误 | 登录页内联提示，不清空账号 |
| 403 | 40301 | 无权限 | 提示并返回上一页 |
| 404 | 40401 | 资源不存在 | 空状态页 |
| 409 | 40901 | 资源冲突（如重复词） | 提示具体冲突项 |
| 422 | 42201 | 业务规则拒绝 | 提示原因，不重试 |
| 429 | 42901 | 频率超限 | 提示稍后再试 |
| 500 | 50001 | 内部错误 | 提示并提供 traceId |
| 503 | 50301 | 依赖不可用（数据库 / LLM / 采集） | 降级提示，不影响已加载内容 |

> 校验失败时 `data` 返回字段级错误：
> `{"field": "password", "reason": "长度至少 6 位"}` 的数组。

## 3. 鉴权

- 登录成功后返回 JWT（HS256），默认有效期 12 小时。
- 后续请求携带 `Authorization: Bearer <token>`。
- 除 `POST /auth/login` 与 `GET /health` 外，**所有接口都要求鉴权**。
- 401 一律走统一错误码 `40101`，前端拦截后跳登录并带 `redirect`。

## 4. 分页与排序

请求参数：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `page` | int | 1 | 从 1 开始 |
| `pageSize` | int | 10 | 最大 100 |
| `sort` | string | `score_desc` | `score_desc` / `time_desc` / `time_asc` |

响应：

```json
{
  "items": [],
  "total": 24,
  "page": 1,
  "pageSize": 10
}
```

## 7. 线索接口

### GET `/leads`

查询参数：

| 参数 | 类型 | 说明 |
|---|---|---|
| `platform` | string[] | 逗号分隔，如 `zhihu,xhs` |
| `stage` | string[] | 同上 |
| `identity` | string[] | 同上 |
| `status` | string[] | 同上 |
| `minScore` | int | 0–100 |
| `keyword` | string | 全文匹配（原文/摘要/标题/来源词/昵称/竞品） |
| `onlyValid` | bool | 默认 `true` |
| `page` / `pageSize` / `sort` | | 见第 4 节 |

  "id": 12,

```json
{
  "identityNote": "提到「我们厂」「要上系统」，判断为决策人",
  "signals": [
    { "word": "厂家推荐", "kind": "intent", "weight": 90, "snippet": "厂家推荐" }
  ],
  "score": {
    "total": 95,
    "grade": "S",

      { "key": "intent", "label": "意向词强度", "weight": 30, "raw": 96, "contribution": 28.8 }

```

### PATCH `/leads/{id}`

```json
{ "status": "contacted", "ownerId": 1, "note": "已在评论区互动" }
```

- 只允许更新 `status` / `ownerId`；其余字段由采集与判定流程维护。
- 状态变更自动写入一条 `lead_activities`。
- 返回更新后的详情。

### POST `/leads/{id}/activities`

```json
{ "action": "添加跟进", "note": "对方回复了预算范围" }
```

返回新建记录。`action` 枚举：`添加跟进` / `状态变更` / `分配负责人` / `生成作业单`。

### GET `/leads/{id}/action-sheet`

```json
{
  "where": "知乎 · 《有没有做机械加工 ERP 的厂家推荐？》",
  "action": "当天公开回答/评论，优先响应（决策期线索，时效性最关键）",
  "angle": "20 人机械加工厂上线 ERP，重点需求为排产管理与物料管理",
  "script": "看到你在确认发票和交付周期……",
  "cautions": [
    "仅通过平台公开评论区/回答区互动，不使用私信批量触达",
    "不索取、不存储对方联系方式以外的身份信息，遵守 PIPL 最小必要原则",
    "同一用户 24 小时内只公开互动一次，避免被判定为骚扰"

```

> 契约层面禁止返回：用户 ID、主页链接、头像、手机号、微信、邮箱。
> 若未来新增字段，必须通过合规评审并在 `08-合规与数据边界.md` 登记。

## 8. 词包与任务

### GET `/keyword-packs`

```json
{
  "items": [
    { "id": 1, "name": "企业数字化", "description": "ERP/CRM/进销存", "enabled": true,
      "counts": { "noise": 4, "intent": 12, "identity": 8, "stage": 6 } }
  ]
}
```

### POST `/keywords`

```json
{ "packId": 1, "word": "求推荐", "kind": "intent", "weight": 70, "platforms": [] }
```

- `word` 在同一词包内唯一，重复返回 `409 / 40901`。
- `platforms` 为空数组表示全平台。
- 新增后由后台任务重算受影响线索（异步，接口立即返回）。

### POST `/tasks/{id}/run`

- 返回 `202`：`{ "runId": 18, "status": "running" }`。
- 同一任务在 `running` 状态下再次触发返回 `409 / 40901`。
- 执行结果通过 `GET /tasks/{id}/runs` 查询。

## 10. 设置接口

### PUT `/settings/scoring-weights`

```json
{ "intent": 30, "stage": 25, "identity": 20, "specificity": 10, "freshness": 10, "engagement": 5 }
```

- 每项 `0–100`，总和必须 > 0。
- 保存后触发异步重算，响应返回 `202` 与 `recalcJobId`。
- 重算期间列表仍可读，使用旧分数，完成后切换。

### POST `/settings/scoring-weights/reset`

恢复默认 `30/25/20/10/10/5`，同样触发重算。

## 11. 前端 store → 接口映射

| 前端 | 调用 | 说明 |
|---|---|---|
| `stores/auth.ts` | `/auth/login`、`/auth/me` | 替换当前写死校验 |
| `stores/leads.ts` | `/leads`、`/leads/{id}`、`PATCH`、`/activities` | 筛选参数与现有 filters 一一对应 |
| `stores/keywords.ts` | `/keyword-packs`、`/keywords` | |
| `stores/keywords.ts`（任务） | `/tasks`、`/tasks/{id}/run` | |
| `stores/system.ts` | `/settings`、`/settings/scoring-weights` | |
| 概览 / 报表 getter | `/analytics/*` | 后端聚合，前端不再本地计算 |

> 迁移原则：接口字段与现有 TypeScript 类型保持一致（camelCase），
> 减少前端改动；差异在 `src/api/mapper.ts` 内消化。
