## 状态标记

| 标记 | 含义 |
|---|---|
| 草案 | 结构已定，细节可能变动，实现前需评审 |
| 评审中 | 待相关方确认 |
| 已定稿 | 当前实现必须遵守；变更需走 ADR |
| 已废弃 | 保留历史，不作为依据 |

## 文档元信息

每篇文档头部必须包含：

```
> 状态：已定稿 ｜ 最后更新：2026-10-20 ｜ 适用版本：原型 v0.1
```

## 维护规则

1. **单一事实来源。** 同一事实只在一处定义，其他文档引用而不复制。
   例如评分权重只在 `01-需求规格.md` 定义，`06-测试与验收.md` 只验证不重述。
2. **改行为必须改文档。** 代码与文档冲突时，已实现部分以代码为事实，
   但冲突本身是缺陷：必须在同一次变更里修正文档或代码。
3. **决策留痕。** 选型、放弃的方案、踩过的坑，写进 `07-决策记录.md`，
   不只写在提交信息里。
4. **不写空模板。** 没有内容的章节直接删除，不保留占位符。
5. **区分已实现与规划中。** 规划中的能力必须显式标注，禁止让读者误以为可用。
