# 06 · 测试与验收

## 1. 测试分层

| 层级 | 工具 | 范围 | 何时跑 |
|---|---|---|---|
| 类型检查 / 构建 | `npm run build` | 前端能否编译 | 每次提交 |
| 单元测试 | Vitest（前端）/ pytest（后端） | 评分、信号匹配、适配器映射 | 每次提交 |
| 接口测试 | pytest + httpx.AsyncClient | 契约、鉴权、错误码、幂等 | 每次提交 |
| E2E | Playwright | 真实浏览器、真实路由、真实构建产物 | 每次提交 + 发版前 |
| 人工验收 | 演示脚本 | 业务可读性与体验 | 发版前 |

## 4. 后端测试计划

| 模块 | 用例 |
|---|---|
| `auth` | 正确/错误密码、token 过期、未带 token 返回 40101 |
| `ingestion` | 同一评论重复导入不新增；字段映射逐平台校验；`source_keyword` join 失败回退 |
| `signal_engine` | 噪声词命中即无效；四层词同时命中；大小写与全半角 |
| `scoring` | 与前端公式一致（同一输入同一输出）；权重变更后重算 |
| `leads API` | 筛选组合、分页边界、排序、更新状态写时间线 |
| `action_sheet` | 不返回任何 PII 字段（断言响应键集合） |
| `settings` | 权重校验（全零拒绝）、恢复默认 |
| `migrations` | 空库 `alembic upgrade head` 成功；`alembic downgrade base` 可回滚 |
| 测试库隔离 | 每个用例跑在独立事务中并回滚；测试库为 `clueradar_test`，不复用开发库 |

**契约测试是硬要求**：所有响应必须通过 Pydantic schema 校验，
且用断言确保响应中**不出现** `userId` / `phone` / `email` / `avatar` / `profileUrl` 等键。

## 7. 环境与执行

```bash
# 正式前端（待实现，骨架尚未创建）
cd frontend
npm run build
npm run dev        # 5273
npm run preview    # 4273

# 产品原型（仅交互评审）
cd prototype
npm run build
npm run dev        # 5273

# 后端（待实现）
cd backend
uv run pytest -q
uv run ruff check .
# 测试库：clueradar_test（由 fixture 执行迁移，不连开发库）
```

E2E 脚本约定：

- 放在仓库外的临时目录或 `e2e/`（V1 起纳入仓库）。
- 必须支持通过环境变量切换目标地址（`BASE`），一次跑 dev + preview。
- 断言失败要打印**实际 URL 与缺失文本**，不能只输出 `FAIL`。

## 8. 已知缺口

| 缺口 | 影响 | 计划 |
|---|---|---|
| 无前端单元测试 | 评分改动靠 E2E 兜底，粒度粗 | V1 补 Vitest |
| 后端尚未实现 | 全部契约未验证 | V1 建 `backend/` 后立即补 |
| 正式前端尚未创建 | 生产构建只有原型，不能直接上线 | 先搭 `frontend/` 骨架，再按页面接 API |
| LLM 判定准确率未评估 | 无法说明"判得准不准" | V1 建 200 条人工标注集 |
| 无性能测试 | 容量目标未验证 | 数据量到 1 万条后压测 |
| 无移动端适配 | 手机不可用 | 明确非目标，暂不排期 |
